# 微博超话每日签到（可迁移版）

一个自包含的 Windows 小工具：定时打开浏览器进微博超话页面完成签到，并验证签到结果。

**核心设计目标是"能带走"**——整个目录拷到任意一台 Windows 电脑上，首次双击会自动补齐运行环境、引导你登录一次，之后就一直复用登录态自动签到，不需要你再做任何事。

---

## 特点

- **免安装 Python**：仓库里带一个 `启动签到.bat`，本机没有 Python 时会自动从 python.org 下载安装（用户级安装，不需要管理员权限）
- **不下载多余浏览器**：优先用系统已装的 Chrome / Edge，只有在两个都没有时才下载 Playwright 自带的 Chromium
- **不打扰你**：日常签到时浏览器窗口挪到屏幕外（`-4000,-4000`），不会突然弹窗抢焦点
- **幂等**：已经签到过就跳过，不会重复点击
- **失败留痕**：出错时写日志 + 截图 + 桌面提醒文件

---

## 快速开始

### 新电脑上第一次用

1. 把整个目录拷过去（U 盘、网盘都行）
2. 双击 **`启动签到.bat`**
3. 按提示走：
   - 没有 Python → 脚本自动下载安装（约 25 MB）
   - 没有依赖 → 自动 `pip install playwright`
   - **没有登录态 → 弹出一个浏览器窗口，请在里面登录微博**
4. 登录成功后，脚本自动完成一次签到，并把「每天 00:00 自动签到」的计划任务注册到这台电脑

之后就不用管了。

### 之后的每一天

计划任务会自动跑，不需要你操作。

想手动跑一次，双击 `启动签到.bat` 就行。

## 为什么换一台电脑必须重新登录

**这是 Windows 的机制，绕不过去，不是本工具的缺陷。**

浏览器的 cookie 用 Windows **DPAPI** 加密，解密密钥绑定"哪台电脑的哪个用户"。把 `profile\` 目录复制到另一台电脑，浏览器解不开里面的 cookie，表现就是"未登录"。

所以"换机重新登录一次"是唯一可行的做法。本工具把这个流程自动化了：检出未登录 → 弹窗让你登录 → 存好 → 继续签到。

**同理，`profile\` 目录不要删**，删了就要重新登录。也**绝对不要提交到 Git**（已在 `.gitignore` 里排除）。

## 为什么不用你日常浏览器的登录态

Chrome 127+ 引入了 **App-Bound Encryption**，cookie 无法离线解密导出；而且浏览器运行时其配置目录被独占，也读不了。

所以本工具用自己独立的 `profile\` 目录，跟你日常使用的浏览器完全隔离，互不影响。

## 命令行

```
python weibo_signin.py                正常跑：检测登录 -> 需要就登录 -> 签到
python weibo_signin.py --dry-run      只检测，不点击（改版排查定位问题时用）
python weibo_signin.py --login        强制进入登录流程（换机、登录态失效时用）
python weibo_signin.py --setup-task   只注册计划任务，不签到
python weibo_signin.py --headless     无界面运行
python weibo_signin.py --no-desktop-alert   失败时不在桌面留提醒
```

**退出码**：`0` 成功或今日已签到 / `1` 失败 / `2` 脚本自身异常

## 目录结构

```
WeiboSignin\
├── 启动签到.bat          双击入口（找/装 Python -> 装依赖 -> 跑签到）
├── weibo_signin.py       主脚本（配置区在文件顶部）
├── setup_env.py          环境自动安装（pip 依赖 + 浏览器通道）
├── tools\
│   └── check_env.py      环境自检（实际启动各浏览器通道验证，不是只看文件在不在）
├── profile\              浏览器配置 + 登录态 ← 不要提交、不要删
├── logs\                 每天一条运行日志
├── screenshots\          签到前后截图（失败时排查用）
└── alerts\               失败提醒文件
```

## 配置

改 `weibo_signin.py` 顶部的 `CONFIG` 字典：

| 键 | 默认值 | 说明 |
|---|---|---|
| `super_name` | `周深超话` | 超话名称，只用于日志显示 |
| `page_url` | 一个超话主页 URL | **换超话改这里**，格式 `https://weibo.com/p/100808<哈希>` |
| `channel_priority` | `["chrome","msedge","bundled"]` | 浏览器通道优先级 |
| `offscreen_position` | `-4000,-4000` | 日常运行的窗口位置（屏幕外） |
| `task_time` | `00:00` | 计划任务每天触发时间 |
| `auto_register_task` | `True` | 首次登录成功后是否自动注册计划任务 |
| `sign_btn_selector` | `[class*='_signBtnOverlay_']` | 签到按钮的定位选择器，改版后可能要调 |
| `login_timeout` | `900` | 首次登录等待秒数 |

## 已知限制

1. **0 点整有跨日风险**。微博按自然日计算签到。如果卡在 00:00:00 执行，页面可能还没刷新、仍显示昨天的「已签到」，脚本会判定为已签到而跳过。**建议把 `task_time` 改成 `00:05`**。
2. **关机时不会执行**。计划任务配了"错过后开机补跑"，所以第二天开机登录后会自动补一次。
3. **登录态会过期**。微博登录有效期不定，失效时脚本会给提示（桌面提醒 + 日志），重新跑 `启动签到.bat` 登录一次即可。
4. **微博改版会导致定位失效**。签到按钮的 class 里带前端构建 hash（如 `_signBtnOverlay_1sn1l_355`），发版就变。脚本用的是前缀包含匹配，小改动能扛住；若完全失效，用 `--dry-run` 跑一次看日志里打印的候选元素，再调 `sign_btn_selector`。

## 签到按钮怎么定位（改版后照这个修）

超话头部「发帖 / 关注 / 签到」一行：

- **未签到**：`DIV`，class 只含 `_signBtnOverlay_<hash>_<n>`，文本「签到」
- **已签到**：同一元素额外挂 `_signBtnActive_<hash>_<n>`，文本「已签到」

两个坑：

- class 里的 hash 段由前端构建工具生成，**发版就变**，所以用前缀包含匹配而非精确匹配
- 页面上的 `今日签到6.7万人 No.56` 是个仅用于展示的 `SPAN`，**不是按钮**，必须用文本精确匹配排除，否则会误点

## 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11（依赖 DPAPI 和计划任务，不支持 macOS / Linux） |
| Python | 3.8+（没有的话 `.bat` 会自动装 3.12） |
| 浏览器 | Chrome、Edge 或 Playwright 自带 Chromium，有任意一个即可 |
| 网络 | 首次需联网装依赖；日常签到需要能访问 `weibo.com` |
